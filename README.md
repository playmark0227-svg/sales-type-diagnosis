# 営業タイプ診断

営業の「タイプ（スタイル）」と「スキル（実力）」を**分けて**測る、ブラウザだけで動く診断ツールです。
サーバー不要・ビルド不要。GitHub Pages にそのまま置けます。

---

## 何が出るか

| セクション | 内容 |
|---|---|
| SALES TYPE | 4文字コード（例：HEPS）＋タイプ名＋キャッチコピー |
| 4軸バランス | H/F・L/E・P/D・S/C を 0〜100% で表示。「ほぼ互角」も明示 |
| 営業特性 | 新規開拓・関係構築・ヒアリング・提案力・クロージング・行動量・戦略性・顧客管理を★1〜5 |
| 強み / 気をつけたいクセ | タイプ別に 5件 / 4件 |
| SALES SKILL | 8スキルを 15〜95点＋レーダーチャート＋総合スコア |
| TOP3 / 伸びしろTOP3 | スキルスコアから自動抽出 |
| 職種適性 | IS / FS / CS / AM / 営業マネージャー を 0〜100 |
| 向いている営業 / 苦手になりやすい仕事 | ◎4件・○3件・▲4件 |
| このタイプの育て方 | マネージャー向け。効果的4件・逆効果4件・配属直後1ヶ月の指示 |
| 成長アドバイス | タイプ由来3件＋スコアが低い3スキルの具体アクション各3件 |
| 相性 | 組むとうまくいくタイプ2件・摩擦が起きやすいタイプ1件 |

---

## 4つの軸

| 軸 | 前者 | 後者 | 何を見ているか |
|---|---|---|---|
| ① | **H** Hunter：新規開拓型 | **F** Farmer：既存深耕型 | どこに向かうか |
| ② | **L** Logic：論理型 | **E** Emotion：共感型 | 何で相手を動かすか |
| ③ | **P** Push：主導型 | **D** Discover：探索型 | どう商談を進めるか |
| ④ | **S** Speed：即行動型 | **C** Careful：慎重型 | どう意思決定するか |

4文字の組み合わせで 16タイプ。

## 設問と採点

### 出題

- **フル版 64問**（タイプ40問＋スキル24問／約8分）
- **ライト版 36問**（タイプ20問＋スキル16問／約4分）

すべて5段階（1 = 全く当てはまらない 〜 5 = 非常に当てはまる）。

> ライト版はフル版の設問から `lite: true` のものだけを出します。
> スキルは8項目あるため、各項目に最低2問を確保して16問にしています（12問だと測れない項目が出るため）。

### タイプ判定

各設問には軸（`axis`）と向き（`dir`）があります。

```
寄与  = dir × (回答 − 3)          →  −2 〜 +2
軸合計 = Σ寄与                     →  −2n 〜 +2n
％    = (軸合計 + 2n) ÷ 4n × 100  →  0 〜 100（100 = 完全に前者側）
```

- 50% 以上なら前者の文字（H / L / P / S）、未満なら後者（F / E / D / C）。
- 各軸10問のうち **5問は逆転項目**（`dir: -1`）です。「なんでも "当てはまる" を選ぶ癖」を打ち消すため。
- 50% に近い軸は「ほぼ互角です」と表示し、隣のタイプも読むよう案内します。

### スキル採点

難易度（`level`）で重みをつけます。できる人しか5を付けない設問を重く見るためです。

```
重み   : level1 = 1.00 / level2 = 1.15 / level3 = 1.32
正規化 : (Σ重み×回答 − Σ重み) ÷ (Σ重み × 4)   → 0〜1
スコア : 15 + 正規化 × 80                      → 15〜95
```

0点や100点を出さないのは、診断体験として意味がないからです。

### 職種適性

```
適性 = スキル適合 × 0.7 + タイプ適合 × 0.3
```

**スキルを主・タイプを従**にしています。そうしないと「タイプが合っているだけで適性が高い」と誤読されるためです。
実力がつけば数字が上がる設計になっています。

### 営業特性★

4軸の連続値から計算します（`js/scoring.js` の `TRAIT_DEFS`）。
スキルスコアは一切混ぜていません。**タイプ ≠ 営業能力**という前提を崩さないためです。

## ファイル構成

```
index.html              画面（4スクリーン：スタート / 設問 / 中間 / 結果）
css/style.css           スタイル。ブランドカラーは冒頭の :root だけ触れば変わります
js/scoring.js           採点ロジック（軸・スキル・特性★・職種適性）
js/app.js               画面制御と結果描画（レーダーチャートは自前SVG）
js/data.js              ★自動生成★ 直接編集しないこと
content/*.json          文章と設問の原本。ここを編集する
tools/build-data.js     content/*.json → js/data.js の変換と検証
```

### 文章を直したいとき

`content/` の JSON を編集して、下記を実行してください。

```bash
node tools/build-data.js
```

構造チェック（16タイプ揃っているか、件数、相性コードが実在するか、軸ごとの問数、ID重複 など）が走り、
問題があれば行を指摘して止まります。

| ファイル | 中身 |
|---|---|
| `content/types-HL.json` | HLPS / HLPC / HLDS / HLDC |
| `content/types-HE.json` | HEPS / HEPC / HEDS / HEDC |
| `content/types-FL.json` | FLPS / FLPC / FLDS / FLDC |
| `content/types-FE.json` | FEPS / FEPC / FEDS / FEDC |
| `content/questions-type.json` | タイプ判定40問 |
| `content/questions-skill.json` | スキル24問 |
| `content/advice.json` | 8スキルの解説・アクション、5職種の定義 |

### 色を変えたいとき

`css/style.css` の先頭：

```css
:root {
  --brand:   #2563eb;   /* メインカラー */
  --brand-2: #0ea5e9;   /* グラデーションのもう一方 */
  --accent:  #f59e0b;   /* スコアのハイライト */
}
```

## 使うときの注意

- 回答はブラウザ内だけで処理され、サーバーには送信されません。途中の回答は `localStorage` に保存され、再訪時に再開できます。
- 自己申告にもとづく行動特性の可視化ツールです。医学的・心理臨床的な診断ではありません。
- **採用の合否や人事評価を単独で決めるために使わないでください。** 面談やアセスメントと組み合わせ、配置・育成の共通言語として使うのが本来の用途です。
